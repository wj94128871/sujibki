업무 내용

[프로젝트 개요]
2차전지 연구개발 과정에서 발생하는 실험 데이터를 자동으로 수집해 하나의 시스템에서 관리하는 웹 시스템을 신규 구축합니다. 측정 장비 8~10종이 내보내는 엑셀 파일을 자동으로 거둬들여 LOT 단위로 묶고, 분석과 시각화를 거쳐 연구노트까지 한 흐름으로 잇습니다.

[추진 배경과 시점]
현재 실험 결과는 측정 장비별 PC에서 고정 양식 엑셀 파일로 각각 나오고 있습니다. 발주처는 이번 구축을 1차 단계로 보고 있으며, 연구 데이터를 인공지능으로 활용하는 것은 그다음 단계로 계획하고 있습니다. 그래서 이번 범위는 인공지능 기능 자체가 아니라, 흩어져 있는 실험 데이터를 나중에 기계가 읽을 수 있는 구조로 쌓아 두는 데까지입니다. 연구노트를 자유 서술로만 남기지 않고 항목과 태그로 구조화해 저장하도록 요구하는 것도 같은 이유입니다.

[난점과 경위]
이 프로젝트의 실질 난이도는 화면 수가 아니라 데이터가 들어오는 입구에 있습니다. 첫째, 측정 장비 8~10종은 기종마다 엑셀 양식이 다르고, 이 파싱이 어긋나면 그 뒤의 이력 추적과 분석이 전부 함께 틀어집니다. 둘째, 장비 PC에 설치되어 상주하는 수집 프로그램은 사람이 지켜보지 않는 상태로 계속 돌아야 하며, 멈추거나 파일을 놓쳐도 즉시 드러나지 않습니다. 셋째, 수집된 원본 파일은 어떤 경로로도 수정되면 안 되고 모든 활동이 기록되어야 합니다. 연구 데이터의 증빙 가치가 여기 달려 있어 설계 초기에 정해야 하고 나중에 덧붙이기 어렵습니다. 제안 시 이 세 가지를 어떻게 다룰지 밝혀 주시기 바랍니다.

[요구사항]
화면은 약 23개이며, 중앙 웹 시스템과 장비 PC에 설치되는 수집 프로그램 두 가지를 만듭니다.

LOT 및 메타데이터 관리
- 규칙 기반 LOT 번호 자동/수동 채번
- 레시피 마스터 등록과 버전 관리
- 제작 시점의 온도·압력 등 환경 수치 자동 매핑
- 성능 테스트 측정 항목 8~10종 정의와 관리
- LOT 검색 시 제작설비-레시피-환경변수-측정결과를 하나의 계통도로 제공
- 특정 변수 변화에 따른 성능 추이 다차원 필터링 조회
- 샘플 상태값 트래킹과 메타데이터 변경 이력 기록

자동 데이터 수집 및 파싱
- 장비 PC 폴더를 감시해 신규 엑셀 파일을 실시간 감지하는 상주 프로그램
- 인트라넷을 통한 중앙 데이터베이스로의 파일·데이터 전송
- 장비별 고정 양식 XLSX/CSV 자동 구조화 파싱
- 원본 파일을 수정 불가 상태로 보관하고 인덱싱
- 데이터 누락·포맷 오류·중복 수집 검증
- 파싱 실패·네트워크 단선 시 오류 기록과 담당자 알림
- 수집 현황과 오류 로그를 확인하고 재처리하는 화면

실험 데이터 분석 및 시각화
- 측정값 기반 성과 지표 자동 계산
- X-Y 산점도·꺾은선 그래프 실시간 생성
- 서로 다른 LOT 샘플 그래프 겹쳐보기
- 축 범위와 Log/Linear 스케일 사용자 정의
- 이상값 필터링과 계산 제외 구간 지정
- 시각화 결과와 연산값을 PDF/Excel로 내보내기

연구자산 관리
- LOT 연계 연구노트 작성
- 비정형 텍스트를 항목·값 형태로 구조화해 저장
- 실험 목적·실패 원인·특이 현상 태그 체계
- 노트 내용과 연관 LOT 통합 검색
- 작성자와 편집 이력 관리

시스템 기반
- 연구원·관리자·최고권한자 권한 분리
- 당일 LOT 현황과 수집 상태를 보는 통합 대시보드
- 조회·수정·다운로드·삭제 전수 활동 로그
- 데이터베이스를 사내 폐쇄망에 정기 자동 백업하고 복구하는 기능

[사용자 스토리와 수용 기준]
- 연구원이 측정을 마치면 결과가 별도 작업 없이 시스템에 들어온다. 장비 PC에 결과 파일이 생성되면 수집 프로그램이 감지해 중앙 서버에 저장하고 해당 LOT에 연결되면 성공으로 본다.
- 연구원이 LOT 하나를 검색하면 그 샘플의 제작 조건과 측정 결과를 한 화면에서 본다. 설비·레시피·환경변수·측정결과가 하나의 계통도로 표시된다.
- 연구원이 특정 조건을 바꿨을 때 성능이 어떻게 달라졌는지 비교한다. 변수와 성능 항목을 지정하면 해당 샘플들의 추이가 그래프로 표시된다.
- 관리자가 수집이 정상인지 확인하고 실패 건을 되살린다. 파싱 실패 건이 목록에 남고 원인 확인 후 재처리할 수 있다.

[업무 상태 흐름]
샘플은 제작 완료, 측정 진행 중, 테스트 완료, 폐기 상태로 관리되며 상태 변경 이력이 남습니다. 수집된 원본 파일은 어떤 경로로도 수정할 수 없어야 하고, 메타데이터 변경은 변경자와 시점이 함께 기록됩니다. 데이터 삭제 권한과 보존 기간은 착수 전 협의로 확정합니다. 화면 전이나 내부 처리 단계 설계는 제안사가 정합니다.

[비기능 요구]
장비 8~10종에서 매일 발생하는 파일을 누락 없이 수집해야 하며, 원본 파일의 무결성이 보장되어야 합니다. 장비 PC에서 중앙 서버로의 전송은 사내 인트라넷을 경유하고, 데이터베이스는 사내 폐쇄망에 정기 백업됩니다. 수집 프로그램은 무인 상태로 상시 동작합니다.

[외부 연동]
외부 시스템 연동은 없습니다. 장비 PC의 파일 시스템을 감시하는 것이 유일한 외부 접점입니다.

[스코프 밖]
과거에 쌓인 엑셀 파일의 일괄 등록과 수동 업로드 화면, 연구노트 텍스트 자동 정제, 인공지능 연동용 데이터 추출 기능은 포함하지 않습니다. 인공지능 관련 기능은 발주처가 추후 도입 단계에서 별도로 진행합니다. 서버 하드웨어 구매도 포함하지 않습니다.

[추가 도입 검토 항목]
아래 세 가지는 이번 계약 범위가 아니며, 발주처가 견적을 확인한 뒤 도입 여부를 판단합니다. 향후 붙일 수 있는 구조로 설계해 주시고, 제안서에 개략 규모를 함께 적어 주시면 검토에 참고합니다.
- 설비 소모품 및 컨디션 모니터링: 제작 설비와 소모품 등록, 제작 횟수·가동시간 자동 집계, 소모품 잔여 수명 산출, 신호등 형태 상태 대시보드, 교체·정비 이력과 임계치 알림.
- 미적분 연산 모듈: 측정 그래프의 피크 검출과 구간 면적 적분 등 현재 외부 툴로 처리하는 연산을 시스템 안에서 수행.
- 서버 인프라 구축: 사내 서버 방식과 폐쇄형 클라우드 방식 중 어느 쪽을 권장하는지, 각각의 구축 범위와 개략 비용, 보안성 비교를 제안서에 포함해 주십시오. 발주처가 아직 방식을 정하지 않았고 이 제안을 받아 결정할 예정입니다.

[제약 사항 및 확인 필요]
운영 환경을 사내 서버로 할지 폐쇄형 클라우드로 할지 발주처가 아직 정하지 않았습니다. 이번 개발 범위는 어느 쪽이든 그 위에서 동작하는 시스템까지이며, 방식 결정은 제안을 받아 진행합니다. 측정 장비 8~10종의 실제 기종과 엑셀 양식 실물은 착수 전 제공되며, 양식이 기종마다 크게 다르거나 병합셀·다중 시트 구조인 경우 파싱 범위가 달라질 수 있습니다. 연구원 수와 동시 사용 규모, 측정 항목별 단위와 이상값 판정 기준, 보고서 내보내기 양식은 착수 전 협의로 정합니다.

[기술 스택]
언어·프레임워크·데이터베이스 지정은 없습니다. 제안사가 제안합니다. 운영 환경(사내 서버 또는 폐쇄형 클라우드)도 확정 전이며 제안을 받아 정합니다. 장비 PC에 설치되는 수집 프로그램의 대상 운영체제는 착수 전 확인해 통보합니다.

[원하는 파트너]
사용자 PC에 설치되어 무인으로 상주 동작하는 프로그램을 만들고 배포·갱신까지 다뤄본 경험이 있는 개발사를 찾습니다. 양식이 제각각인 엑셀·CSV를 안정적으로 구조화해 본 경험을 중요하게 봅니다. 측정·실험 데이터를 그래프로 다뤄본 경험과, 서버 인프라 방식을 비용·보안 관점에서 비교해 제안할 수 있는 역량을 우대합니다. 요구사항이 아직 구체화되는 중이라, 발주처와 협의하며 요구를 정리하고 문서로 확정해 본 경험을 특히 중요하게 봅니다.

[제안 요청 사항]
제안서에 다음을 포함해 주십시오. 장비마다 다른 엑셀 양식을 어떻게 파싱하고 양식이 바뀌었을 때 어떻게 대응하는지. 상주 수집 프로그램의 장애를 어떻게 감지하고 복구하는지, 놓친 파일을 어떻게 되살리는지. 사내 서버와 폐쇄형 클라우드 중 권장 방식과 그 근거. 예상 착수·완료 일정.

[예산과 기간]
예산은 협의로 정합니다. 기간은 순수 개발 약 3개월을 기준으로 하되, 요구사항 확정 협의·장비 양식 확보·검수 일정은 협의로 정합니다.

[산출물]
요구사항정의서와 기능정의서, 중앙 웹 시스템, 장비 PC용 수집 프로그램과 설치 패키지, 데이터베이스 스키마, 장비별 엑셀 양식 매핑 정의서, 설치·운영 매뉴얼, 연구원 대상 사용 교육을 납품합니다.

[계약 특이사항]
요구사항은 착수 초기 정의 단계에서 발주처와 함께 확정하며, 그 확정본이 개발 범위의 기준이 됩니다. 이후 추가되는 요구는 변경 절차로 협의합니다. 장비 엑셀 양식 제공 시점과 운영 환경 방식 결정 시점에 따라 착수일이 조정될 수 있습니다.
