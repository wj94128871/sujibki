요구사항 정의서 (Requirements)

항목 내용
프로젝트명 시장조사·분석 대시보드 (Market Dashboard)
산출 팀 요구사항팀 (requirements-team)
요청 원문 "수집 크롤링을 통한 자료취합 후 시장조사와 분석등을 통한 내용들을 한눈에 볼수있는 대시보드페이지가 필요해"
작업 규모 모드 standard (판정 근거는 §9 참고)

1. 개요 (배경)

SI(외주/프리랜서 매칭) 사이트 — 대표적으로 위시켓, 프리모아 등 — 에 올라오는 프로젝트 의뢰(안건)를 월 단위로 크롤링하여 수집한다.
수집된 안건 내용을 바탕으로 시장조사와 기능 추가·개선 방향 분석을 수행하고,
이를 통해 플랫폼을 오픈했을 때 시장성이 있는 내용을 도출하여 한눈에 보기 쉬운 대시보드 페이지로 제공하는 시스템을 구축한다.

"데이터 수집(크롤링) → 분석(시장조사·기능 개선 방향) → 시장성 인사이트 도출 → 시각화 대시보드"의 파이프라인 전체를 대상으로 한다.

2. 목표 / 비목표

2.1 목표 (Goals)

  • G1. SI 매칭 사이트(위시켓·프리모아 등)의 프로젝트 안건을 월 단위 주기로 자동 수집한다.
  • G2. 수집 데이터를 정제·저장하여 각 사이트별 안건 목록/요약을 제공한다.
  • G3. 수집 내용을 기반으로 시장조사(수요·트렌드·공급 동향)와 기능 추가·개선 방향을 분석한다.
  • G4. 플랫폼 오픈 시 시장성이 있을 만한 내용(인사이트)을 도출한다.
  • G5. G2~G4 결과를 한눈에 보기 쉬운 대시보드 페이지로 시각화·요약 제공한다.

2.2 비목표 (Non-Goals)

  • NG1. 의뢰·프로젝트의 입찰/계약/매칭 자동화 기능은 만들지 않는다. (수집·분석·시각화에 한정)
  • NG2. 외주사/개발자 계정·프로필 관리·메신저 기능은 만들지 않는다.
  • NG3. 실시간(분/초 단위) 수집·반영은 하지 않는다. (월 단위 배치)
  • NG4. 수집 대상이 아닌 사이트(위시켓·프리모아 외 일반 웹 전역)의 광범위 크롤링은 제외.
  • NG5. 사용자 로그인/권한 관리, 멀티테넌시(사용자별 데이터 격리)는 만들지 않는다.

3. 타깃 사용자

  • 주 사용자: 요청 팀(팀 단위 사용). 개인/관리자 1명 이상이 대시보드를 열람.
  • 성격: 비개발·개발자가 함께 볼 수 있는 직관적인 시각화 요약을 선호.
  • 접근: 별도 로그인/권한 없이 웹 페이지(URL)로 접근.

4. 범위

4.1 포함 (In Scope)

영역 내용
데이터 수집 위시켓·프리모아 등 SI 매칭 사이트의 안건(프로젝트 의뢰) 크롤링
수집 주기 월 1회(월 단위) 자동 배치 수집
데이터 관리 수집 데이터 정제, 중복 제거, 표준화, 저장(DB)
시장 분석 수집 안건 기반 시장조사(수요·트렌드·카테고리·예산·기간 분포), 기능 추가·개선 방향 분석
인사이트 도출 플랫폼 오픈 시 시장성이 있는 내용(신규 수요 카테고리, 고성장 키워드 등) 도출
대시보드 사이트별 수집 목록/요약, 분석 결과, 시장성 인사이트를 한눈에 보는 시각화 페이지

4.2 제외 (Excluded)

  • 입찰/계약/결제/매칭 자동화
  • 회원가입/로그인/권한/관리자 기능
  • 실시간 수집 및 밀리초 단위 갱신
  • 수집 대상 외 사이트의 무분별한 크롤링

5. 기능 요구사항 (Functional Requirements)

우선순위: M=필수(Must) / S=선택(Should) / C=고려(Could)

ID 우선순위 요구사항 수용 기준(AC) 초안
FR-01 M 위시켓·프리모아 등 SI 사이트의 안건(프로젝트 의뢰) 크롤링 대상 사이트 목록의 안건이 정기 수집되어 DB에 저장된다
FR-02 M 월 1회(월 단위) 자동 수집 배치 월 단위 스케줄로 크롤러가 자동 실행되고 결과가 기록된다
FR-03 M 수집 데이터 정제·표준화·중복 제거 동일 안건 중복 저장되지 않고, 필드(제목·예산·기간·카테고리 등)가 표준화된다
FR-04 M 수집 데이터 저장(DB) 정제된 데이터가 Neon 등의 관계형 DB에 저장·조회 가능하다
FR-05 M 사이트별 수집 안건 목록/요약 제공 사이트별로 안건 목록과 핵심 요약을 보여준다
FR-06 M 시장조사(수요·트렌드·분포 분석) 수집 안건 기반 시장 지표(카테고리별 수요, 예산·기간 분포, 트렌드 등)를 산출·제공한다
FR-07 M 기능 추가·개선 방향 분석 수집 내용으로부터 플랫폼에 필요한 기능 추가/개선 방향을 도출·제공한다
FR-08 M 시장성 인사이트 도출 플랫폼 오픈 시 시장성이 있을 내용(신규 수요·고성장 영역)을 도출해 보여준다
FR-09 M 한눈에 보기 쉬운 대시보드 UI/UX 시각화 요약(차트·카드·표) 중심의 직관적 단일 페이지를 제공한다
FR-10 S 대시보드 상세 드릴다운 요약에서 개별 안건 상세/원문·출처 조회 가능 (필요 시)
FR-11 S 수집 이력/실행 상태 표시 최근 수집 시점, 수집 건수, 실패 안내를 보여준다

6. 비기능 요구사항 (NFR)

ID 구분 요구사항
NFR-01 기술 스택 Cloudflare(Workers/Pages) + Neon(PostgreSQL) + Rust + Python 기반으로 구성
NFR-02 성능 대시보드 페이지 로딩이 빠르며(최대한 빠르게), 데이터 크기에 관계없이 실용적 응답
NFR-03 실행 환경 배포 가능한 웹 페이지 형태로 제공 (로그인/권한 없이 URL 접근)
NFR-04 유지보수 수집 대상 사이트 변경·분석 로직 변경이 용이한 구조
NFR-05 견고성 크롤링 실패(사이트 구조 변경 등) 시 무한 재시도·중복 저장 방지, 오류 기록
NFR-06 보안/법적 크롤링 대상 사이트 이용약관·로봇 규약(robots.txt), 과도한 요청·개인정보 수집 최소화 고려

7. 데이터 요구사항

  • 수집 대상: SI(외주/프리랜서 매칭) 관련 사이트 — 위시켓, 프리모아 등 (대상 후보는 리서치팀이 확정)
  • 수집 항목(추정): 안건 제목, 내용/요약, 카테고리/업종, 예산, 기간, 모집 인력/기술 스택, 등록일 등
  • 수집 주기: 월 1회 (월 단위 배치)
  • 저장: Neon(PostgreSQL)에 정제·표준화하여 저장
  • 분석 대상: 수집된 안건 텍스트·속성 기반 시장조사 및 기능 개선 방향, 시장성 인사이트

8. 성공 기준 (Success Criteria)

사용자 명시: "제대로 된 수집" 과 "제대로 된 분석" 이 핵심.

  • SC-1. 제대로 된 수집: 대상 SI 사이트의 안건이 월 단위로 누락 없이(또는 실패 내역이 명확히 기록되며) 수집되고, 중복·정제 오류 없이 DB에 저장된다.
  • SC-2. 제대로 된 분석: 수집 데이터를 근거로 한 시장조사 지표와 기능 추가·개선 방향, 시장성 인사이트가 산출·대시보드에 표시된다.
  • SC-3. 한눈에 보기: 사이트별 수집 요약, 분석 결과, 시장성 인사이트를 한 화면에서 직관적으로 확인 가능하다.
  • SC-4. 접근성: 로그인 없이 웹 URL로 팀원이 접근하여 대시보드를 열람할 수 있다.

9. 작업 규모 모드 판정

  • 판정: standard
  • 근거:
  • 신규 서비스(대시보드 플랫폼) 구축에 해당.
  • 요구사항 수: 핵심 기능 11개(FR-01~11) + NFR·데이터 요구로 5~20개 범위에 해당.
  • 조사 필요: 수집 대상 사이트(위시켓·프리모아 등) 접근성·구조·robots 규약, 경쟁·유사 대시보드, 시장조사 방법론 등 리서치 필요.
  • 9단계 전체 파이프라인(리서치→기획→디자인→개발→QA)을 적용.
  • (small 아님: 단일 기능이 아니며 조사·분석·시각화 다단계 내재 · full 아님: 출시급 대형·요구 20개+ 미만)

10. 제약 사항

  • 기술 스택 고정: Cloudflare + Neon + Rust + Python (가능한 빨리 구축)
  • 별도 로그인/권한 인프라 없음
  • 월 단위 데이터 특성상 대용량·실시간 요구 없음
  • 외주·프리랜서 매칭 사이트의 이용약관/로봇 규약 준수 필요

11. 가정 (Assumptions)

  • A1. 크롤링은 Python 기반으로 구현하고, 백엔드/API·배포는 Cloudflare(+Rust) 로 구성하는 것을 전제로 한다 (기술 배분은 개발팀 세부 설계 시 확정).
  • A2. "한눈에 보기"는 단일 웹 대시보드 페이지의 시각적 요약(차트·카드·표) 를 의미한다.
  • A3. 수집 대상 사이트는 위시켓·프리모아 외 유사 SI 매칭 사이트 포함 가능 (리서치팀이 확정).
  • A4. 분석은 수집 안건 데이터 기반 정량(분포·추이) + 정성(기능 개선 방향)을 결합한다.

12. 오픈 질문 (Open Questions)

# 질문 담당/귀결
OQ-1 수집 출처 사이트 확정 목록(위시켓·프리모아 외 추가 여부) 리서치팀 확인
OQ-2 크롤링 대상 사이트의 접근성(로그인 필요 여부)·robots 허용 범위 리서치팀 확인
OQ-3 대시보드 상세 드릴다운(FR-10)을 MVP에 포함할지 여부 기획팀 우선순위 결정
OQ-4 분석 결과를 제시할 구체 지표(카테고리 수요 점유율, 예산 분포 등) 확정 기획팀/리서치팀 확정
OQ-5 월 1회 수집 시점·배치 실행 환경(스케줄러) 지정 개발팀 설계
