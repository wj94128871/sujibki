  • 레벨 표기: U=단위 / I=통합 / E=End-to-End(UI) / C=계약(API)

1. 테스트 전략 요약

  • 레벨: 크롤러(단위+통합) → 정제/적재(통합) → 분석(단위/통합) → API(계약) → 대시보드(End-to-End).
  • 데이터: 실제 크롤 샘플(crawled/) 활용 + 소스별 최소 데이터셋 시드.
  • 초점(성공기준 SC): SC-1 수집 무결성(누락·중복·실패 기록), SC-2 분석 산출, SC-3 한눈에 보기, SC-4 로그인 없이 접근.
  • 도구: pytest(크롤러·정제·분석), API 계약 테스트(웹 요청), Playwright/웹 E2E(대시보드). 저신뢰 수치·null·경계값 중점.

3. 테스트 케이스 상세 (주요 골격)

TC-06 개인정보 제외 (프리모아 client_id) — 중요

  • Given 프리모아 수집 응답(목록 JSON)에 client_id(이메일)이 포함
  • When 정제·적재 파이프라인 실행 후 projects 조회
  • Then ① 적재 컬럼에 이메일 값 없음 ② raw_json에도 client_id 미포함 ③ 대시보드 어디에도 이메일 미노출
  • 경계: client_id가 비이메일 토큰(예: lduckh)인 경우도 포함·제외 여부를 컬럼 명세로 결정(저장 제외 원칙).

TC-15 중복 제거 (멱등)

  • Given 동일 원본URL·source의 안건이 이미 있고 동일 런 재실행
  • When 재적재
  • Then 같은 (source, source_ref) 행이 새로 추가되지 않음(upsert), 건수 유지.

TC-29 저신뢰 수치 단정 금지

  • Given 시장성 인사이트에 신뢰도 낮음(low) 항목 존재(예: 마케팅성 수치)
  • When 인사이트 표시
  • Then ① 신뢰 뱃지(낮음) 표시 ② "~로 추정/공지", 단정 표현(값 절대 확정) 없음 ③ 정확한 확정 수치 문구 검출 시 실패.

TC-31 반응형·차트

  • Given 다양한 뷰포트(모바일 375px / 데스크톱 1280px) + 소량 데이터
  • When 대시보드 렌더
  • Then 차트·카드·표가 넘침 없이 정상 표시, 스크롤/터치 가능.
