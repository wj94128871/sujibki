  • 본 plan.md는 요구사항(requirements.md)을 구체화한 PRD(제품 요구사항)다. 요구사항문서의 내용을 변경하지 않으며, 기능 우선순위·수용 기준(AC)·MVP 범위·리스크를 확정한다.

1. 제품 개요 (Overview)

1.1 한 줄 정의

SI(외주/프리랜서) 매칭 사이트(위시켓·프리모아), 스타트업 공모(모두의창업 u300), 해커톤(Devpost)의 안건 데이터를 주기적으로 크롤링·표준화 저장하고, 이를 바탕으로 시장조사 지표·기능 개선 방향·시장성 인사이트를 한눈에 보는 단일 웹 대시보드로 제공하는 시스템.

1.2 문제 / 가치

  • 문제: 외주·프리랜서·스타트업·해커톤 수요는 여러 출처에 흩어져 있고, "어떤 카테고리/기술/예산이 커지고 있는가"를 수치로 판단하기 어렵다. 각 사이트 UI가 달라 직접 비교·취합이 번거롭다.
  • 가치(차별화): 여러 출처 안건을 표준 스키마로 통합·정규화해 카테고리·예산·기간·지역·기술 키워드 분포와 월간 추이(어느 영역이 커지는지)를 수치로 제시 → "플랫폼/사업을 열면 어느 영역이 시장성이 있는가"의 근거를 제공(성공기준 SC-2).

1.3 타깃 사용자 · 접근

  • 주 사용자: 요청 팀(팀 단위, 개인/관리자 1명 이상 열람), 비개발·개발자 모두가 직관적으로 읽는 시각화 요약 선호.
  • 접근: 로그인/권한 없이 웹 URL로 접근 (NG5·NFR-03).

Then 카테고리별 안건 수·점유율 차트 표시(전체+소스별)		 • 미분류 카테고리는 "기타"로 집계
AC-06-2 예산/기간 분포 Given budget·period 값 존재
When 분포 차트 요청
Then 예산 구간 히스토그램·기간(일) 분포 표시(null 제외, 별도 카운트 표기)		 • null 예산 건은 분포 제외+건수 별도 고지
AC-06-3 상주vs도급 비중 Given work_type 값 존재
When 비중 차트 요청
Then 도급/기간제/상주(및 해커톤·공모) 비중 표시		 • 값 없으면 "기타"
AC-06-4 기술 키워드 트렌드 Given 기술키워드 필드 존재
When 키워드 랭킹 요청
Then 상위 키워드 빈도(전체+월간 변화) 표시		 • 키워드 없으면 공백
AC-06-5 월간 등록 추이 Given 등록일 데이터 존재
When 추이 차트 요청
Then 월별 신규 등록 건수 시계열 표시		 • 월별 데이터 부족 시 레이블 안내

FR-07 — 기능 개선 방향 분석

AC-07 Given/When/Then Edge Case
AC-07-1 Given 수집 안건·공급 동향(지원자 수·레벨) 존재
When "기능 개선 방향" 섹션 요청
Then ① 수요가 많고 공급이 부족한 영역/요구 패턴(예: 공통 요구사항) 도출 ② 개선 후보 목록·근거(건수/추이) 표시		 • 분석 근거 데이터 부족 시 "분석 미실행" 안내(확정 수치 미표기)

FR-08 — 시장성 인사이트 도출

AC-08 Given/When/Then Edge Case
AC-08-1 Given 정제 안건·월간 추이 존재
When "시장성 인사이트" 섹션 요청
Then ① 고성장 카테고리/키워드(증가율 또는 건수 기반) 표시 ② 근거(수치·기간) 함께 표기 ③ 저신뢰 수치는 신뢰도 주석과 함께 표기, 정확한 수치 단정 금지		 • 증가율 계산 데이터 부족 시 계산 제외·주석
AC-08-2 Given 시장성 인사이트 존재
When 카드/표로 표시
Then 카테고리명·건수·추이(+/▲)·근거기간 표시		 • 단일 시점 데이터는 "추이 미확인" 주석

FR-09 — 대시보드 UI/UX (한눈에)

AC-09 Given/When/Then Edge Case
AC-09-1 Given 대시보드 URL 접근
When 페이지 로드
Then ① 헤더 요약 카드(총 건수·최근 수집·소스별 건수) ② 소스별 현황 ③ 시장조사 분석(차트) ④ 기능 개선 방향 ⑤ 시장성 인사이트 ⑥ 수집 이력이 한 화면에서 스크롤 없이 눈에 들어오는 레이아웃으로 표시		 • 데이터 없으면 빈 상태 안내(로딩·에러 구분)
AC-09-2 Given 대시보드 로드 완료
When 차트/카드 렌더링
Then 차트·카드·표가 반응형(모바일/데스크톱)으로 정상 표시		 • 짧은 데이터에서도 차트 깨짐 없음

FR-10 — 상세 드릴다운 (S)

AC-10 Given/When/Then Edge Case

Then DB 필드 기반 상세 + 원본URL "원본 보기" 링크 표시(MVP)		 • 필드 null은 "정보 없음"
AC-10-2 전체 상세 (S) Given Phase 2 로그인 항목 포함 상세 데이터 존재
When 상세 열람
Then 모집 요건·근무 환경 등 상세 표시		 • 로그인 데이터 부재 시 안내

FR-11 — 수집 이력·상태 (S, MVP 최소 포함)

AC-11 Given/When/Then Edge Case

When 수집 상태 섹션 요청
Then 최근 수집 시각·소스별 건수·상태 표시		 • 이력 없으면 "아직 수집 없음"
AC-11-2 Given 수집 부분 실패 존재
When 상태 확인
Then 실패 내역(건수·원인) 표시		 • 실패 원인 미기록 시 "원인 미상"

6. MVP 범위 (Phase 1) / Phase 2 · Phase 3

Phase 1 — MVP (필수)

  • 데이터: 위시켓·프리모아(도급), u300 현재+1기, Devpost — 5종 수집·정제·저장 (크롤러 이미 준비)
  • 기능: FR-01~09 전부 + FR-10 경량(원본링크) + FR-11 최소 수집 이력
  • 대시보드: 단일 페이지 — 헤더 요약 카드 / 소스별 현황 / 시장조사 분석(카테고리·예산·기간·상주·키워드·월간추이 차트) / 기능 개선 방향 / 시장성 인사이트 / 수집 이력
  • 분석 로직: 정량(분포·추이·점유율) 규칙 기반 + 정성 인사이트(수동/규칙 템플릿). 저신뢰 수치 주석.
  • 기술: Cloudflare(Workers/Pages) + Neon(PostgreSQL) + Rust(API/분석 보조) + Python(크롤러·분석). 상세는 trd.md.

Phase 2 (Should)

  • FR-10 전체 상세(로그인 항목 포함, 선택적 수집), FR-11 고급(수집 실패 원인·대시보드 고도화)
  • 추가 크롤러: 크몽·Freemo·CyanNest·아임잡 (robots 허용 확인됨 / 원티드긱스 제외)
  • 월 1회 완전 자동 배치(스케줄러 고도화, 알림)
  • 자동 수집 스케줄러 무인 실행 정착

Phase 3 (Could)

  • 시장성 점수(복합 지표) 자동 산출 고도화, 비교 뷰(소스 간·기간 간), 데이터 내보내기(CSV), 알림/구독, 역사적 데이터 누적 장기 추이

7.2 가정 (Assumptions)

  • A1 크롤러는 Python, 백엔드·API·배포는 Cloudflare(+Rust), DB는 Neon (trd.md에서 확정).
  • A2 "한눈에" = 단일 웹 페이지의 시각적 요약(차트·카드·표).
  • A3 수집 주기는 월 1회; MVP는 on-demand + 이력, 자동 스케줄은 Phase 2.
  • A4 분석 = 정량(분포·추이) + 정성(기능 방향), 수치 근거 우선.
  • A5 크롤러 실행 환경(curl_cffi venv vs lzstring venv 분리)은 trd.md에서 격리 설계.
